# PiPo 学习 Agent

PiPo 现在由模型自主选择工具，服务端执行工具，把真实观察返回模型，循环直至回复或达到预算。不是关键词匹配，也不是仅将自由聊天接到模型。

## 演示

1. 启动 Python 服务，打开 PiPo，填写团队 AI 口令。
2. 输入“根据我的进度安排下一步，并带我开始”。观察回复中的工具记录以及具体课程页面。
3. 完成真实学习后再问“检查我的错题，挑一道针对性练习”。PiPo 重新读取当前状态，调用现有推荐规则，再打开具体题目。
4. 输入“选择一个我还没通过的编程任务”，或追问某个 Python 概念。
5. 展开工具记录，区分模型实际调用、被拒绝的操作与最终回复。自然语言内容仍可能出错，需要人工判断。

## 工具与约束

- progress：课程解锁/通过状态、作答统计、到期题、最近5条错题理由及已通过编程任务。
- lesson：概念定义、导学内容及当前课程状态。
- recommend：通过原有规则引擎选出最多3道同章题目，不向模型传标准答案字段。
- coding：编程任务列表与是否通过。
- open_content：只允许打开已被工具检查过的课程、练习或任务；检查课程锁定；每轮最多1次页面打开。

模型最多调用5轮、合计8次工具；每次模型请求共享服务器60次/小时额度。服务端保留GLM-4.7密钥，浏览器口令只用于本地HTTP鉴权，不进入模型提示词。模型只能操作固定工具，没有shell、任意网络、文件修改、自动判分或代替学生完成学习的权限。

对话在页面内存中保留最近消息，不写入SQLite。发给模型的内容包括目标、最近最多8条对话及工具结果。错题理由每条截取500字符。代码草稿不通过工具发送。停止会取消浏览器等待，防止后续页面操作；已发出的服务端模型请求未必随之停止。

服务端路径：POST /api/agent。学习状态经validate_state验证。输入上限1000字符，历史限制8条；团队口令、Origin、Host、请求大小限制沿用原有安全机制。错误时返回明确失败，页面不执行待处理动作。

## 验证

新增tests/test_agent.py验证真实多轮工具观察与执行过程、非法ID、锁定课程、单动作限制、推荐信息、次数上限和无额度时不联网；tests/test_http.py验证Agent接口授权、输入和失败响应。现有回归测试一同执行。模型由模拟响应替代，没有产生付费调用。网页已进行类型检查和生产构建。真实GLM-4.7模型的工具选择质量、端到端真实模型体验仍需团队配置后验证。

旧版PPT及旧讲稿中如有“PiPo只是关键词导航”，展示时应使用本说明的新流程；不得把模拟测试称为真实模型效果评估。
