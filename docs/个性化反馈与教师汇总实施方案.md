# 个性化反馈、教师汇总与API选择

状态：以下是下一阶段可执行方案，尚未接入云API或实现教师汇总页面。当前应用的真实AI入口是Ollama候选标签与原文引用；没有偷偷调用付费模型。

## 个性化反馈

输入只包含题目、标准答案与经审核解析、候选误区、学生理由、提示使用情况，以及必要的近期同概念表现。把学生理由放在数据字段中，不接受其中的命令。建议返回固定结构：concept（候选ID或unknown）、quote（原文）、explanation（短解释）、hint（下一步思考提示）。练习ID由现有规则推荐器决定，模型不能凭空创建题目或改答案。

实现位置：为edu/ai.py增加服务适配器和结果校验，再在edu/ui.py中显示“AI辅助反馈”。检查字段类型、长度、枚举、引用逐字存在；只要超时、拒绝或校验失败就显示原固定反馈。结构化输出保证格式的能力不等于语义正确，解释仍需人工评估。

先完成一个API供应商，保留Ollama和无AI模式。将API Key放在环境变量，不能写入源码、题库、导出记录或截图；公共演示版通过服务端代理调用。请求设置超时、输出长度、费用额度，并记录模型版本、提示版本、延迟、状态和token用量。变更提示词或模型后重新跑冻结评估集。

验收：明确误区/手误/含糊理由得到不同而有依据的反馈；断网仍能答题和保存；恶意理由不能修改标准答案；每条建议对应当前概念；人工检查知识性错误。

## 教师汇总不需要大模型

最小可行版：每位学生使用本地数据库，通过带匿名学习者ID和版本号的文件导出；教师导入多份文件查看汇总。不必先做登录、联网同步或多人系统。

当前“导出学习记录”仍是选择题列表，不含匿名学习者身份及代码提交，不能直接当成已经完成的班级汇总协议。下一步定义新版本格式，保留旧版导入兼容：schema_version、learner_id、exported_at、attempts、code_attempts。不要把API密钥混入导出。

导入时验证类型、时间、题号/任务号；用（匿名学习者ID、记录类型、记录ID）去重，发现同键内容冲突需提示，不静默覆盖。只有一个人的数据时明确显示“1位学习者”。仅代码学习者也应出现在名单中。

教师页建议四块：

1. 章节概览：参与人数、独立作答数、选择题首次正确率、代码任务完成率。
2. 概念薄弱项：同一学生多次重复不重复计算为多名学生；区分规则候选与AI诊断。
3. 学生明细：课程状态、是否用提示、需复习概念、代码任务通过情况。
4. 诊断质量：人工复核结果与AI失败比例；不把unknown算成确定不懂。

完成率分母写清楚是全部任务/分配任务；缺失记录不是0分，不自动生成高低能力排名。未人工确认的误区用“可能涉及”呈现。验收至少包含两位模拟学习者、重复导入、损坏文件、归档题目和仅代码记录；明确这些是演示数据。

## API建议（2026-10-03查阅官方文档）

| 方案 | 建议用途 | 接入关注点 |
|---|---|---|
| 阿里云百炼Qwen | 团队先试一个账号可用的、支持JSON Schema的Plus/Flash模型 | 官方列表目前包含Qwen3.7-Plus与Qwen3.8-Flash等；选择具体可用快照与地域，不能假定所有模型/思考模式支持同样参数 |
| OpenAI GPT-4.1 mini | 为短理由分类与结构化反馈做一个非推理模型基线 | 官方列明支持Structured Outputs；可固定gpt-4.1-mini-2025-04-14快照；是否优于其他模型需本项目评估 |
| DeepSeek | 可作为另一供应商对照 | 官方提供JSON Output指南；JSON有效仍需字段和语义检查；模型名按控制台与最新文档选择 |
| Ollama本地模型 | 当前接口即可使用，适合离线原型 | 速度取决于机器与模型；必须同样评估，不能因为本地就认为诊断正确 |

本项目的选型建议是先试百炼，再用同一冻结数据比较一个替代模型。不是已有实测排行榜。按团队所在地、账号支持地域与实际价格选择；设置小额预算后再测，不需要上来买最高档模型。ChatGPT订阅不是应用API凭据，应用调用需独立配置可用服务。
