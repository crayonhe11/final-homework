# AI 根据学生理由辅助诊断：怎样证明有用

当前没有真实模型效果结论。现有Ollama接口仅在答错且理由非空时，从“错误选项对应的候选概念”与unknown中选择；不会发现候选集合外的新误区，也不会诊断“答对但理由错误”。固定模板反馈与自由生成反馈是不同功能。

## 准备独立样例

建议用30条开发样例调试，再准备60条冻结测试样例。数量是课程项目建议，不是统计充分性保证。三章和15个概念尽量覆盖：确实误解、知道规则但手误、理由含糊、解释相互矛盾、试图让模型忽略规则、空理由、正确选项。正确和空理由的样例要单独报告跳过行为。

同一个理由仅换数字的变体放在同一分组，避免一份进入开发集另一份进入测试集。内置heldout.json已经用于开发与演示，不能继续宣称是未接触的正式测试集。模拟答案必须标注模拟；真实学生理由先去掉姓名等身份信息。

教育成员与编程成员各自独立标注，先不看系统结果。标注问题ID、选项、原理由、目标概念或unknown、支持证据、来源、标注者与分歧处理。意见不一致时讨论形成共识；记录共识前一致率与分歧原因。不能仅凭错误选项推导人工标签。

评估输入是JSON数组，字段与evaluation/heldout.json一致：question_id、choice、reason、expected；来源与人工标注记录单独保存。错误但证据不足的expected为字符串unknown；正确答案没有误区时为JSON null。测试前冻结数据文件与模型/提示版本。

## 同一数据比较两条路线

- A：只按错误选项映射，输出候选概念。
- B：规则+AI；AI有效时使用候选概念/unknown，无效或超时则回退规则。

在项目目录运行：

```sh
python3 evaluation/evaluate.py --dataset evaluation/heldout.json --output evaluation/rules-run.json
# 先配置EDU_OLLAMA_MODEL为本机已安装的模型名，再执行：
python3 evaluation/evaluate.py --ai --dataset evaluation/heldout.json --output evaluation/ai-run.json
```

正式验收时用独立冻结文件替换--dataset路径。报告保存数据哈希、模型名、逐例预测、匹配结果、调用耗时、状态数量、一致率和宏平均F1。宏F1对实际出现的真实/预测标签取平均，unknown与null也参与；汇报时同时给每个概念的样本量，避免掩盖类别覆盖不足。

自动报告不是完整教育评估。另由两名人工评阅者检查：引用是否真的支持结论、反馈有没有知识性错误、语气是否武断、提示是否给了可执行的下一步；自由生成反馈接入以后也必须加入这项检查。

## 报告必须包含

| 指标 | 用途 |
|---|---|
| 规则/组合方案一致率与宏F1 | 比较同一数据上的标签表现 |
| AI有效返回数、跳过数、失败回退数 | 防止把全部回退误称为AI有效 |
| unknown比例及正确拒判案例 | 检查系统是否敢于承认证据不足 |
| 每个概念的混淆与样本量 | 查出特定概念误诊 |
| 人工核验的知识错误/证据不支持数 | JSON格式正确不代表内容正确 |
| 调用延迟、中位数/P95、实际费用 | 评估使用体验与成本；本地模型无API账单 |
| 改善/退步/两者都错的具体案例 | 给老师可检查的证据，不只报百分比 |

可预先设定演示验收目标：有效结果>=95%，所测反馈知识错误为0，组合方案至少不劣于规则且能纠正明确手误案例；这些是建议门槛，不是已达到的结果。零错误只指当前样本，不能推断永远无错。

如果希望证明提高学习成绩，还需要真实学生、前后测、对照条件与更长观察期；本轮诊断标签比较不能支持这类结论。
