# GitHub 项目对比与本项目改进

调研日期：2026-09-30。采用官方仓库及维护者文档作为依据，范围是适合三十题、单人本地 Python 课程原型的设计，不以仓库星数替代技术判断。

## 对比结论

| 参考项目与可核实来源 | 值得借鉴的设计 | 原版不足 | 本次落地 |
|---|---|---|---|
| [Exercism Python 配置](https://github.com/exercism/python/blob/main/config.json) | 将概念、前置概念、练习和难度作为显式元数据组织 | 主要按题号和难度选题，没有概念学习顺序 | 新增 prerequisites/order；优先建议满足基础的概念，未满足时给出学习建议，不硬锁 |
| [Py-FSRS 官方仓库](https://github.com/open-spaced-repetition/py-fsrs) | 复习事件产生下一次到期时间，复习日志与调度有明确关系 | 已做题仅按做题顺序排序，不考虑经过的时间 | 新增 UTC 到期调度、学习页入口和逐概念下次复习时间；仅借鉴事件与到期队列思想 |
| [freeCodeCamp curriculum 贡献指南](https://github.com/freeCodeCamp/curriculum/blob/dev/docs/CONTRIBUTING.md) | 题目内容有结构化定义，并用测试检验题目与解答 | 只有基础字段检查，新增题时容易遗漏解析或制造循环前置关系 | 扩充字段、重复选项、难度、主题、提示、误区依据和前置关系循环检查，新增异常数据测试 |

第三个来源是 **2019 年归档的历史仓库**，只用于比较稳定的内容验证原则，不把它的旧 Node/MongoDB 版本或旧构建命令用于本项目。前两个仓库的 main 分支会继续变化；本文链接是本次查阅的入口，不声称绑定某个固定提交。

## 自主实现与取舍

### 1. 从“挑一题”到可解释的学习顺序

`data/learning_design.json` 保存十五个概念的前置关系与第一层提示，由 `data/build_bank.py` 生成题库和概念表。`edu/bank.py` 检查引用存在性和循环依赖。

`next_practice()`：同主题到期题优先；无到期题时，优先选前置概念已初步稳定的新题，再考虑难度、教学顺序。缺少满足条件的题仍允许继续，但显示建议先巩固的概念。与 Exercism 的完整学习路径系统相比，这里采用建议式路径，适合小题库。

答题后的 `recommend()` 仍优先推荐未做同概念变式，接着才是到期复习、其他新题、提前复习。当前题始终排除，排序可复现。

### 2. 到期复习，不引入未经校准的记忆预测

`edu/scheduler.py` 从作答日志重建复习状态：

- 错误作答：10 分钟后，阶段归零。
- 首次独立正确：1 天后。
- 到期后独立正确：依次 3、7、14、30 天，上限 30 天。
- 提前独立正确：保留原到期时间与阶段，不靠短时间刷题推迟复习。
- 使用提示或提示状态未知：不提升阶段；首次/到期作答安排 1 天后，提前作答保留较早到期日。
- 无效旧时间：不参与调度；无时区旧时间按 UTC 解释。

这些间隔是本项目自主选择的演示参数。**没有使用或复现 FSRS 的权重、遗忘曲线、参数优化或期望保持率计算，也不把选择题对错直接伪装成 FSRS 的四档自评。**后续若有足够真实日志，可以另外评估是否接入 py-fsrs。

### 3. 提示与独立表现分开

两层提示先给思考方向，再展示原有规则。数据库新增 `hints_used`，旧记录保留 NULL 以表示未知。最近三次均独立答对且至少覆盖两道不同题才可标记初步稳定。提示使用本身不算错误，也不会把看提示答对当成独立理解的充分证据。

这项是对本地代码检查发现问题后的自主改进，不宣称来自上述仓库的某个具体实现。

### 4. 数据兼容与内容质量

保留旧题号、标准答案、现有 SQLite 记录和 Git 历史。数据库升级可重复运行，旧数据不清空。题目从当前题库移除时，旧记录仍能查看、导出。首次正确率按题号去重，与所有作答累计正确次数区分。

内容校验在启动时运行，但不执行学生输入。固定题目的执行测试仍是维护者测试的一部分。

## 修改定位

| 文件 | 作用 |
|---|---|
| `edu/scheduler.py` | 纯函数调度，可注入测试时间 |
| `edu/engine.py` | 选题、推荐、独立作答统计与首次表现 |
| `edu/storage.py` | 可重复执行的旧表迁移、提示次数存储 |
| `edu/bank.py` | 字段及前置概念图验证 |
| `edu/ui.py` | 两层提示、到期复习按钮、时间与首次正确率、长文本滚动条 |
| `main.py` | 命令行也使用相同的选题规则 |
| `data/learning_design.json` | 本项目自主编写的前置关系、引导提示 |
| `tests/test_learning.py` | 新增十七项回归测试 |
| `tests/smoke_ui.py` | 扩展桌面提示、到期题与归档记录验证 |

## 验证与限制

30 项单元/集成测试覆盖原功能与新增规则；30 道原题答案仍逐题执行核验。桌面测试使用临时数据库，不污染学习记录。真实模型的诊断效果仍未验证；本轮重点改善学习流程，没有改变模型或声称 AI 准确率提高。

题库只有每概念两道题，重复记忆的影响仍明显。提示、前置关系、诊断标签和间隔参数需要教育成员复核。未引入账号、网站服务、任意代码执行或新依赖。

## 来源与代码使用说明

本轮仅借鉴设计，未复制上述仓库代码、测试代码、题目或素材，因此没有引入第三方源码文件。README 的本地运行方式保持不变。未来如果直接引入代码或依赖，需要针对当时版本另行核查许可证及归属要求。

## 后续修正：从前置标签到完整课程层

用户指出，单独给推荐加前置关系还不是可见的学习架构。本轮因此增加首页知识地图、基础导学、十五课讲解、显式课程作答和章节解锁。原有“仅建议、不硬锁”的模式保留为自由练习；课程闯关需要满足前置关卡。本项目仍是三个主题的有限课程，不等同于 Exercism 的完整课程体系。

详见 [课程架构与过关规则](课程架构与过关规则.md)。
