# AI讲解、诊断推荐与真实验证

## 当前实现

接入Kimi/Ollama后，对“答错且理由非空”的选择题一次请求同时生成候选误区、学生原文引用、个性化讲解与下一步提示。答对或理由为空不调用；AI默认关闭。模型密钥优先从api_config.json读取，文件不存在时兼容环境变量，不读取项目.env，不保存到学习数据库。

AI解释必须返回正确的标准选项、来自题库解析的逐字引用，以及长度合规的讲解/提示。诊断合法但讲解不合格时，保留诊断并回退固定解析；诊断标签/学生引用不合法或请求失败则整个AI结果回退。引用存在、字段合法不等于语义正确，因此界面同时保留标准解析，并标注AI内容需核对。题库解析本身仍待团队人工签核，不夸大为已审核。

该版本只从错误选项对应的候选概念与unknown中选择，不诊断全部可能误区。也不分析“选对但理由错误”。个性化讲解基于本题与本次理由，不等于长期学习画像或多轮辅导。

## 推荐如何改变

- 规则模式/AI失败：沿用现有推荐排序。
- AI理由支持候选误区：优先未做的同概念变式，说明推荐依据来自本次理由；不声称确定诊断。
- AI证据不足：取消同概念补练优先，先到期复习，再按难度推荐同章未做题，最后已做题；用中性措辞邀请验证。

推荐只能选固定题库，排除当前题、不跨章，模型不能编造题号。不同策略未必每次推荐不同题，需同时看策略说明。自由练习底部“下一题”与第一条推荐一致；课程模式仍按原通关条件继续，并增加“不计闯关”的AI课外验证入口。AI不修改答案分数或课程过关状态。

## 1. 连通性验证

填写api_config.json后，在项目目录执行：

```sh
python3 evaluation/check_connection.py
```

默认只检查配置是否存在，不请求模型、不验证密钥是否有效。要发起最多一次真实请求（会产生API用量）：

```sh
python3 evaluation/check_connection.py --live
```

结果写入runtime/ai-connection.json。分别报告是否收到API响应、诊断格式是否有效、讲解格式与依据检查是否通过，并记录调用状态和耗时。连接成功不能说明诊断正确。网络或格式失败退出码为1，没有自动重试。

## 2. 诊断与讲解评估

默认不调用模型的规则基线：

```sh
python3 evaluation/evaluate.py --output runtime/rules-report.json
```

明确触发真实AI评估，内置12条样例最多12次请求：

```sh
python3 evaluation/evaluate.py --ai --max-calls 12 --output runtime/kimi-report.json
```

运行前验证整个数据集与请求上限，超出则停止且不调用。--max-calls限制请求次数，不是金额上限；价格与实际费用以供应商控制台为准。每次返回最多请求1200个输出token。模型可用权限、网络、额度仍由真实运行验证。

使用团队独立样例：

```sh
python3 evaluation/evaluate.py --ai --dataset evaluation/team-heldout.json --max-calls 60 --output runtime/team-report.json
```

team-heldout.json由团队自行准备，格式参考heldout.json，每例必须有唯一id、有效question_id/choice、reason及人工expected。内置样例已参与开发，不能当成新的独立测试集。

报告包含规则/组合一致率、宏F1、AI有效率、讲解校验通过数、改善/退步案例ID、推荐题号与策略、数据哈希、模型/提示版本、逐例耗时与供应商返回的token用量。usage_reported_count为0时，token总数0不代表免费或没有消耗。推荐比较采用空历史，便于隔离策略差异；不代表真实个体的长期推荐效果。

每例human_review字段留空，由实际审查者填写知识是否正确、引用是否支持结论、讲解是否有帮助、推荐是否相关、姓名与备注。系统不会把模型自己的自评当作人工审核结论。指标优于规则也不能证明提高真实学习成绩。

## 3. 演示

同一道range(2,5)题，两次均选包含5的错误答案：先写“最后那个数5也要打印出来”，再写“终点5不包括，应该是2、3、4，我点错了”。观察模型是否分别给出候选误区与unknown，解释是否回应理由，推荐策略是否相应改变。以上是预期行为，不是已发生的真实模型测评结果。
